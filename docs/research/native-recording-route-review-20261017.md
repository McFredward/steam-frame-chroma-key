# Complete recording-route repair after native r4

## Native evidence and remaining limit

The consumed r4 run first prepared the original-output clone on the actual
Frame and adopted command generation 25175, then refused UnknownRoute before
any observer draw substitution. Its scalar receipt cannot identify the actual
callback or extension header. Imageless framebuffer Begin is a source-proven
missing route, not a proven explanation for that native run. The Frame was
manually restored and the maintainer confirmed its normal visible/usable UI.

This repair addresses the complete intercepted recording path together. It does
not activate a live opacity presenter, establish source-frame/eye/UV association,
modify the PC Steam sender, or prove visible passthrough. Original rendering
continues on every unsupported route.

## Original operations and recording shapes

The synchronous public decoder supports ordinary legacy/Core2/KHR2 Begin,
Next and End with inline contents. It retains complete bounded header censuses
for all three roots, including headers after the first unsupported one. Portable
attachment Begin, single-device group mask 1 with zero/one area, and bounded
sample-location outer lists are represented. Known vendor transforms, striping,
per-view areas, density offsets, unknown headers, wrong parents, cycles,
duplicates and secondary routes remain explicitly refused.

Original arguments are forwarded verbatim once; no Begin structure or caller
array is rewritten or retained. Zero-count ignored pointers are never followed.
Device-group override areas preserve ignored top-level render areas. Nested
sample-location payloads can depend on image flags and variable sample locations
not known to this adapter. They are not inspected: the original transition state
is forwarded unchanged, and only bounded outer indices are diagnostic facts.
Complete pass/pipeline/source/lifetime tickets remain mandatory for substitution.

Independent source review also found six additional Core/KHR forwarding pairs
that shared a core-preferred stored function: dispatch-base, BeginRendering,
EndRendering, Submit2 and the two indirect-count draw forms. Each now retains
the exact requested original entry. A missing entry is not fabricated from its
nonnull sibling. These repairs do not imply those calls caused the r4 refusal.
Shared passive descriptor alias infrastructure is unchanged; no r4 use is proven.

The actual nine dynamic-state declarations observed in r4 continue to use their
untouched native setters. No new setter interception, compilation, logging, file
I/O, allocation or wait is introduced on the compositor recording path. The
original draw is skipped only after a same-callback target ticket permits the
instrumented exact draw, with immediate original-pipeline restore. Later-draw,
source pairing and retirement protections remain intact; in particular, a
two-subpass pass alone does not authorize reuse of disturbed descriptor state.

## Refusal provenance and bounded output

Every previous direct wrapper UnknownRoute site supplies its exact operation,
including Core/KHR spelling, applicable header shape and public flags/object.
The transaction adds coherent command/pool generations, subpass and recording
phase under its existing guard. Pipeline and target-draw encounters are still
observable after refusal, without minting a new replacement ticket.

A fixed 64-slot immutable census deduplicates ordinary object/draw churn and
maintains atomic repeat counts. A separately reserved first-refusal record
survives a full accepted-event bank. Cold readers use release/acquire publication
without taking the callback guard or observing partially initialized payloads.
Overflow is explicit and no context is evicted. Only a callback that observes an
actual first reason transition can claim its cause. A losing concurrent guard
that wins Contention owns that attribution; a guarded scope cannot steal it.
An earlier unobserved cause stays unavailable rather than being invented later.

Context lines are emitted once independently of the old scalar state hash,
bounded to 2 KiB each. The extra 64 lines, reserved first failure and overflow
fit with all prior creation/graphics receipts inside the existing 512-KiB/256-
event progress budget. Repeated counters do not generate per-poll output.
Snapshot JSON keeps only the first cause and compact final counts (at most
6 KiB extra); ordinary JSON remains limited to 16 KiB. A reporting failure is
explicit, never silently promoted to successful capture.

## Validation scope

- Recording-shape decoder: 131 focused normal and ASan/UBSan/leak checks; strict
  ARM compilation. Includes ignored poisoned pointers, bounds, complete census
  and original pointer forwarding models.
- Provenance: 95 focused transaction checks and 58 Bridge checks, each normal
  and ASan/UBSan/leak. Concurrent cold readers, bank saturation, delayed winning
  contention and post-refusal target observations are covered. Both owned
  translation units compile for ARM with warnings as errors.
- Actual exported Snapshot translation unit: 766 public checks and 1615 complete
  recording-route checks, each normal and ASan/UBSan/leak. Private pinned shader
  definitions and fake original dispatch are used in the latter; this is not a
  native GPU execution. It covers exact aliases, all nine native setters, full
  accepted public recording chains, same-callback target substitution/restore,
  original submit and owned completion marker. Source pairing is honestly refused
  when the fixture has no independently recorded raw copy.
- Passive-only and Journal-only conditional builds compile; full ARM shared
  build with no undefined imports succeeds. Existing host GPU pass/dynamic-state
  proofs from r4 are inherited because those owners and shaders are unchanged.
  They are not relabelled as new native evidence or rerun unnecessarily.

The public context and exact-hook modes have separate CTest entries. Integration,
exact ARM ABI/imports, loader, staging, hosted CI and cleanup receipts are kept
privately in `build/private-native-r5-integration-20261017/`. Each worker's small
logs/source pins/results survive removal of its generated compilation caches.

Any next device action requires fresh concrete permission and readiness after
the final package is checked. Loading and later rollback each use one agreed
restart. There is no automatic expiry, rollback or restart timer. A successful
next observer record would prove the original invocation's sampled data path;
it would still precede source-frame/eye registration and visible native opacity.
